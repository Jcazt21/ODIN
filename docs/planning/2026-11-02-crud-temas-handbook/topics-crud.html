2.1.1

INTRODUCTION.

The /topics module is read-only in the frontend, although the backend already provides POST, PUT and DELETE on /api/topics, soft delete, a hierarchical tree and the classifier cache. This plan lets a user administer the catalog from the UI without touching the database: list as a tree, create with an optional parent, edit name and description, activate or deactivate, and delete (figure 2.1-1).

2.1.2

FUNCTIONAL DESCRIPTION.

Work runs in four packages after four baseline prerequisites: backend (13 tasks), frontend contracts (4), components (9) and integration (5), as in figure 2.1-2. The client has not sent its topic list, so the CRUD assumes no structure: the parent is optional and the catalog works flat or hierarchical. Create and edit are inline, as in AliasManager.tsx, because the repo has no form modal.

2.1.2.1

Task Rule.

Every task writes its test, watches it fail for the stated reason, implements the minimum, goes green and ticks its checkbox (figure 2.1-10). Characterization tests are born green and say so.

2.1.4

PACKAGE 1 · SLUG AND DESCRIPTION.

A user types only the name of a topic. TopicPayload.slug becomes optional (max 160 characters) and create_topic resolves it as in figure 2.1-3: an explicit slug is kept, otherwise the slug is derived from the name with slugify (text_norm.py). A blank description is stored as NULL, never as an empty string. After each successful write the classifier catalog cache is invalidated (figure 2.1-4).

2.1.4.1

Slug Rule.

slugify strips accents, lowercases, replaces each run of characters outside a–z and 0–9 with one hyphen, and trims hyphens at both ends. A name that yields an empty slug is answered with 422.

2.1.6

PACKAGE 1 · TREE, WRITE AND DELETE CONTRACT.

TopicNode gains is_active, description, display_order (T-B6) and child_count (T-B7), so the UI can dim inactive rows and preload the edit form. PUT, DELETE, authentication and cache invalidation are fixed by characterization tests that are born green. DELETE keeps returning 204 whether it deactivates or erases (figure 2.1-5).

2.1.6.1

Delete Rule.

A topic with articles, or with any child including inactive ones, is only deactivated. An empty topic is erased together with its aliases, because the SQLite tests do not enforce ON DELETE CASCADE (T-B9).

2.1.8

PACKAGES 2 AND 3 · FRONTEND.

Package 2 carries the contract to the browser: regenerated api-types.ts, the createTopic, updateTopic and deleteTopic client, flattenTopicTree with the new fields and three mutation hooks that invalidate topicKeys.all. Package 3 builds NewTopicForm and TopicRowCells in src/components/topics/. TopicRowCells moves between the modes of figure 2.1-7; task order is in figure 2.1-8.

2.1.8.1

Dimming Rule.

When is_active is false the text cells carry opacity-45 and the action cells do not, so a dimmed row stays operable. The switch is role="switch" with aria-checked.
